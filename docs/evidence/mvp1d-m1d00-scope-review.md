## Scope and trust boundary

Untrusted bytes enter as a project-contained regular `.sh` host file, never as host-shell text. A secure descriptor-relative, no-follow, size-bounded reader must bind pathname, inode/metadata and exact SHA-256 bytes through validation and staging. Path normalization must accept documented CLI forms such as `./test.sh` without accepting project escapes or symlink components. Source replacement, in-place mutation, hard-link/metadata ambiguity and unsafe file kinds must fail closed; a prior pathname validation is not authorization to reopen it. A private, exact-byte staging source must not be replaced between verification and Docker transfer.

Only an owner-verified Docker/binfmt target container receives the script. KEEMU generates `/opt/tmp/keemu-script-<digest>-<run-unique>.sh` (digest plus unique component prevents two identical concurrent inputs claiming the same object); neither host basename nor user input selects the target path. Verify target parent and final object are not symlinks/special entries, refuse collision and any overwrite, re-inspect full container ID and labels before/after mutation, and compare the target's exact bytes to the source SHA-256 before execution. `docker cp` alone does not establish no-overwrite or target integrity. Cleanup checks exact path and object identity, removes only this run's object, and records unsafe/missing/colliding state without deleting another user's object. Persistent mode must serialize or otherwise prove staging namespace ownership under concurrent calls.

Execute `/bin/sh TARGET_SCRIPT` with separate bounded argv, default explicit `/opt` cwd, validated target cwd, default 60-second timeout (1–600 seconds under the current Docker command bound), no host shell, no arbitrary host env, no stdin/TTY and no target privilege escalation. Existing `DockerRuntime.exec()` times out and kills the *local Docker CLI process*, not necessarily the target process or descendants: a new scoped target process-tree protocol needs exact identity, bounded TERM/KILL escalation and survivor checks, including fork/daemonization and PID reuse. On uncertain ownership or surviving descendants, never signal unrelated persistent services or claim PASS; owner-verified one-shot container teardown can contain one-shot uncertainty, but persistent mode must fail closed with explicit recovery state. `timeout-child.sh` must only run in an owned isolated target with a shorter runner deadline; its `sleep 120` is a test stimulus, not permission for an unbounded test.

Output capture stays separate and bounded; report actual exit, timeout, duration, per-stream truncation and cleanup independently. Assertions on incomplete/truncated streams cannot claim an absence proof. An unexpected exit/assertion on complete evidence is FAIL, missing capability or changed locked input is BLOCKED, harness contract/cleanup failure is ERROR (never PASS), and PASS requires real target execution, all required assertions and verified cleanup. Arbitrary script output can contain secrets: fixtures contain none; later report design must prevent raw secret-bearing host inputs or output from entering Git or reports while preserving a usable bounded diagnostic contract. Do not infer physical Keenetic compatibility from a generic userspace run.

Do not add mounts, Docker socket, privileged/host PID/network namespace, host shell, public ports, arbitrary host environment, host binfmt/module/firewall mutation, physical-device access or automatic package/network installation. Docker daemon access is a host privilege on the *harness* side, not something to expose to target. Cleanup authority is exact run-owned full IDs and exact staged paths, never a name/label-only sweep or `docker system prune`.

## Existing boundaries independently inspected

- `src/keemu/input_paths.py:92` validates relative containment but explicitly says validation is not a safe open; `src/keemu/lifecycle.py:77` has descriptor-relative no-follow reading for existing IPK inputs. Script size, mutation/reopen and staging must be specified separately, without pretending this IPK helper already closes every script race.
- `src/keemu/docker_runtime.py:31,448,522` has IPK-only `STAGED_IPK` target regex and `docker cp`; broadening that regex would weaken IPK staging. `exec()` bounds nonempty argv to 128 elements/4096 chars each and delegates to `_exec` with 600-second maximum and 1 MiB per-stream cap; `_exec` kills only the local command process group. Script arguments (including empty positional values) and aggregate command budget require an explicit reviewed contract, not implicit inheritance of an incompatible validator. `copy_file` checks source `lstat` and container identity but does not establish target no-overwrite or target digest.
- `src/keemu/persistent.py:496` holds a registry lock and re-inspects the actual container before `exec`; current `exec` returns only exit/stdout/stderr, with no staged-file, timeout, truncation or report contract. Existing `keemu exec NAME -- COMMAND` parsing in `src/keemu/cli.py:287` requires compatibility tests for `--script` and `-- ARGS`.
- `src/keemu/scenarios.py:166,180,235,302` defines discriminated checks and path validation; `src/keemu/input_locks.py:74,108` binds scenario and source hashes. A new script check must bind its script source in the production lock, reopen/recheck on use, update `schemas/scenario.schema.json` and model parity, and keep existing version-1 scenarios valid. It must use the shared staging/execution path, not `/bin/sh -c` of file contents.
- `src/keemu/models.py:168` defines the strict schema-version-2 report and aggregate priority; script metadata needs a typed, schema-parity-tested extension with separate cleanup and truncated-stream semantics. `src/keemu/reports.py` retains write-once bundles. Do not rewrite historical report bundles.
- `src/keemu/docker_runtime.py:277` creates isolated bounded fresh containers with dropped capabilities and no mounts/host namespace/ports; `src/keemu/lifecycle.py:179` owns disposable IPK cleanup, while persistent registry has distinct lifecycle. Reuse these boundaries only after actual identity and runtime checks. The original AArch64 generic lifecycle exists; MIPS/MIPSEL root execution probes alone do not grant a generic script lifecycle. Same runner contract on both; truthful BLOCKED is allowed pending general lifecycle availability.
