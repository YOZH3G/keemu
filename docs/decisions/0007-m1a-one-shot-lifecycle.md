# ADR-0007 — MVP 1A one-shot IPK lifecycle

Status: implemented and verified for m1a-13; A02–A06/A18/A21 remain partial as whole acceptance IDs.

`keemu test --scenario PATH --lock PATH` runs a disposable, locked AArch64 IPK scenario without creating a persistent environment. It validates schema/profile/source/base hashes and source confinement, copies the exact verified bytes to private local staging, statically inspects that copy, verifies the prepared offline cache and live image, then creates only run-owned Docker resources. Docker copy-back of the staged target IPK is hashed before real target `opkg install`; the feed is not updated. Installed package/file inventory, explicit scenario checks, HTTP target-loopback readiness and refused connection after stop, real `opkg remove`, package absence and Docker diff are checked before owner-verified cleanup. An installer-started service is probed before explicit start to avoid duplicate startup. A previously existing run ID is a collision, never cleanup authority.

The pinned base includes the BusyBox gzip applet but no `/opt/bin/gzip` link required by target opkg archive handling. The runner checks the applet and link absence, adds the link only in the disposable container before recording the baseline, and records a substitution. No base image, host binary or feed artifact is modified. Residual comparison exempts exact observed opkg bookkeeping paths and baseline directory metadata; other changes must match scenario-listed allowed residual paths. Docker diff records path/change metadata, not file bytes, deleted/recreated identity or all processes/sockets; the HTTP stop check proves a refused target-loopback connection at its probe instant only. Report limitations state the narrower evidence.

Each stage records its outcome; nonzero target exit is FAIL, unavailable/uncertain prerequisites are BLOCKED, malformed input is ERROR, and command timeout is ERROR with `timed_out=true`. The primary failure remains referenced to its exact operation even when cleanup fails; cleanup adds its own ERROR and may raise overall status to ERROR. A `finally` path attempts target stop/removal, only run-owned container/network cleanup, and read-only reconciliation. Process termination outside Python `finally`, daemon loss, stale registry recovery and cleanup retries are not covered by this slice. Write-once JSON/Markdown/operation-log bundles retain validated scenario and lock bytes, bounded captured command output and optional metadata diff; publication failure fails closed rather than claiming a report.

The real opt-in Docker/binfmt test exercises synthetic hello postinst-once and failure, static locked AArch64 web-demo readiness/stop, startup failure, target command timeout and an injected cleanup-reporting failure after actual owner-checked removal. Static defects fail before Docker. No host publishing, HTTPS, UDP, MIPS/MIPSEL, persistent registry, interruption recovery, exhaustive socket/process census or full A02–A06/A18/A21 acceptance is claimed. See `docs/traceability.md` for per-ID gaps.
