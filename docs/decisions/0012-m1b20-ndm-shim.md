# ADR-0012: Strict local NDM process shim (m1b-20)

Status: accepted for the bounded synthetic process-contract slice; not device compatibility evidence.

`src/keemu/ndm.py` exposes `python -m keemu.ndm --contract FILE --state FILE --log FILE --run-id ID -- ndmc -c 'command'`. The version-1 JSON contract declares exact argv, stdout, stderr, exit code, source (`synthetic:` or `observed:`), initial state, and read/write semantics. Only `ndmc -c` is supported in this slice. No program invokes a physical Keenetic or asserts an observed device sample. Tests generate a clearly synthetic demonstration contract; none of its response bytes is represented as a Keenetic response.

A read selects an exact response for its current declared state. A write must have exit 0 in its declared response, change a modeled value, and have an observable read contract for every possible value. Repeating a write with no change fails exit 65. Unknown exact argv fails exit 64, emits `unsupported-ndm-command`, and never changes state. `required_check(64)` returns required BLOCKED, cause `environment`, mode `shim`, evidence `environment-gap: unsupported-ndm-command`; it does not blame the package. Other nonzero shim outcomes do not become PASS. Contract changes invalidate persisted state by canonical model digest. An interprocess flock serializes local state and log operations; state replacement is fsynced and atomic. This is a cooperative local process contract, not an adversarial same-UID or target-container isolation boundary.

`ndmc.jsonl` records timestamp, run ID, redacted argv, empty environment allowlist, exit code, duration, fixture source and event. It never logs stdout/stderr, command arguments or arbitrary environment values. Runtime output still follows the declared process contract; callers must treat it as potentially sensitive. Contract validation rejects ambiguous duplicate keys, unexpected fields/versions, duplicate argv, unobservable mutations and incomplete state reads. Files use no-follow reads and owner checks; state/log/lock are local and owner-only. Logs and state are not automatically attached to the existing one-shot report bundle.

The CLI is a host Python process invoked explicitly. It is not placed at `/opt/bin/ndmc` in any Entware image, not wired into `keemu test` or `up`, and has no target-architecture executable or observed physical-device fixture. Therefore A11's process semantics have portable proof, but real package invocation/known observed fixture and full A11/MVP 1B acceptance remain BLOCKED until a later authorized lifecycle slice. m1b-21 event-handler execution is not part of this ADR.
