# ADR-0015 — Disposable internal Docker topology (m1c-23)

Status: implemented and exercised on the shared Docker Engine 29.7.2 host. This is an A13 routing slice, not MVP 1C packet-processing acceptance.

Use two separate, `--internal` Docker bridge networks with exact per-run `/24` IPv4 IPAM, and three containers from the immutable AArch64 base. A project-local `flock` serializes allocation; enumerate and inspect every Docker network's actual IPAM, supplement it with worker-visible routes, then choose two non-overlapping pools from `10.224.0.0/12`. Docker's IPAM allocation also rejects concurrent overlap outside that lock. These are dynamic run addresses, not the specification's illustrative `192.168.50.0/24` and `10.10.10.0/24` defaults. The Docker-host route table is not readable from this worker namespace; allocation does not claim collision detection against unrelated non-Docker host routes. Stop if Docker IPAM fails rather than forcing a pool.

The client attaches only to LAN, server only to WAN, router to both; none attaches to management/host networking and no ports are published. Verified Docker IDs provide the control plane through `docker exec`, so no management network is created in this slice. The client default route points at router LAN; server has a specific LAN reverse route through router WAN. Router creates a real `br0` via target BusyBox `ip link add ... type bridge`, moves the LAN address onto it and enslaves the actual LAN interface. Docker's per-endpoint `com.docker.network.endpoint.ifname=wan0` names WAN without relying on eth numbering. Docker's namespace-scoped `net.ipv4.ip_forward=1` sysctl enables routing; no NAT or firewall rule is installed. `brctl` and target `ip link set ... name` were tried but failed under QEMU's ioctl translation (`Inappropriate ioctl for device`); neither is silently represented as working. No module load is attempted: already-loaded bridge support is required before creation.

Only `NET_ADMIN` is added to the three disposable nodes for route/bridge setup; `SYS_MODULE`, privilege, host namespaces, binds, volumes, Docker socket and publish remain forbidden. Docker inspect verifies applied capabilities and endpoints before setup; full ID plus owner/run/base/target labels gates each mutation. Pre-ID interruption is recoverable because names derive from the validated run ID: `cleanup(run_id, image_id)` discovers run-labeled resources, re-inspects full IDs and exact role names, removes containers before networks, refuses unexpected/foreign resources, then checks absence. Ordinary failures roll back with the same path. Recovery is explicit; no automatic crash-resume report/registry was added. A same-UID adversary racing Docker labels/names is outside the cooperative lock guarantee.
