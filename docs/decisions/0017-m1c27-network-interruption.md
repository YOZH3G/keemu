# ADR-0017 — Scoped network interruption and foreign policy-rule isolation

Status: verified for frozen m1c-27 AArch64 topology regression; A18/A20 whole-ID acceptance remains PARTIAL.

Use the actual `topology.create` path in a separate Python process, then SIGKILL that exact creator after (1) first internal network create, (2) first container create with both networks allocated, and (3) completed routed topology setup. Record the unexpected owned IDs before invoking only `topology.cleanup(run_id, image_id)` twice. Full-ID/owner/run/base/target re-inspection permits recovery without a returned topology object or pre-ID registry record; the second cleanup is idempotent. A wrong-run attempt to remove a foreign container must fail before mutation.

A second, test-owned AArch64 topology represents a foreign run throughout all three cases. A native, image-ID-pinned, read-only/no-mount helper joins only its client network namespace to dump IPv4 policy rules; an explicitly NET_ADMIN-bounded invocation adds one sentinel destination `/32` priority-17271 rule in that same namespace. The static AArch64 BusyBox `ip rule` call returned `Operation not supported`, so it is not used as the observer. Each pre/post-kill and post-recovery rule dump must match byte-for-byte, while global Docker container/network identity and selected state snapshots must match before and after each recovery and at final postflight. The helper is ephemeral and uses no host namespaces, privileged mode, SYS_MODULE, bind mount or publish. Inspect the interrupted project's containers for no prohibited mounts/namespaces/privilege/capabilities and exact CPU/RAM/PID/log bounds, and its networks for internal bridge mode.

`tests/integration/test_m1c27_network_interruption.py` passed live with three SIGKILL barriers. `docs/evidence/m1c27-network-interruption.json` is byte-identical to the ignored run report, SHA-256 `6d60b47c6e4b284b1d615e401f46579ad8f2fbd2f3e0ecf83c939a79e2a32537`. It records owned resource counts (0 containers/1 network; 1/2; 3/2), exact IDs, four unchanged foreign IPv4 policy-rule records at each boundary, unchanged foreign Docker resources and a final baseline of two unrelated containers/four networks. Final owner-label queries were empty. The test neither installs nor enumerates host/firewall rules, loads a host module, creates a target NFQUEUE rule, or proves automatic crash recovery or an A21 interrupted report. It proves foreign routing-policy rules, not firewall-rule parity; those limits stay explicit rather than promoting A18/A20 or MVP 1C to full PASS.
